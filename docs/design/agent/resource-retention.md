# 运行资源与附件回收

> 历史设计说明：本文涉及的固定流水线已移除。当前实现、持久化事件与恢复 API 以[静态图指南](static-agent-graph.md)和[单 Agent API](operator-only-api.md)为准。

Core 通过 OperatorFabric 提供 RetireRun、ArtifactRoots、CollectArtifacts；SQLite 和文件系统实现位于 Extension。回收默认不自动执行，由宿主配置保留时间、执行时机和外部附件根。

## 调用顺序

1. 暂停新运行、上传、会话附件更新和消费任务，等待在途操作结束。维护屏障必须覆盖所有进程，以及根引用快照到清理结束的全过程。
2. 对终态运行执行 RetireRun，指定 tenant、run_id、now_ms、retention_ms，先 dry_run 查看报告，再按同一策略执行。保留时间必须为正数；从该运行最近事件或回执时间计算。
3. 收集会话仍持有的附件 BlobId；执行 ArtifactRoots 取得 Fabric 的引用根。
4. 内嵌 FabricBlobStore 使用 CollectArtifacts，将会话附件传入 external_roots。文件系统使用 FilesystemBlobStore::collect_artifacts，传入 Fabric 根与会话根的并集。两者都设置正数 grace_ms，并先 dry_run。
5. 记录回收报告，再恢复运行。

文件系统实例及其 clone 内部有读写锁，防止清理与本实例上传/读取交错；它无法替宿主锁住其他实例、进程或会话数据库。内嵌回收拒绝活跃租约，但这也不替代跨存储维护屏障。

## 保留与失败语义

运行有未发布 outbox、未确认事件或有效租约时不能退休。运行删除其公开日志、专属 checkpoint、订阅、回执和死信；事件槽位和 ID 保留，只清除载荷，避免重编号改变其他订阅位置。保留小型退休标记，旧运行读取、重放和重新执行被拒绝。因此此方案回收大型内容，但不承诺元数据恒定大小。

附件清理先遍历仍被引用或在宽限期内的 JSON 对象，包括 journal 的 previous 链，再清理不可达对象。会话外部根必须由宿主提供。无从判断外部会话是否仍引用附件时，不应执行清理。引用损坏或部分对象不完整时停止清理。

Fabric 新上传先写未完成 manifest，再写分块，最后 CAS 标记完成。中断上传只有过宽限期且不被引用才回收。旧版只有分块没有 manifest 的残留首次维护仅记录观察时间，后续维护经过宽限期才删除；dry_run 不启动观察计时。

文件系统只处理 UUID 命名的 .blob、.json 和本实现的隐藏 .tmp 文件；不处理其他文件，遇到受管名称的非普通文件则报错。文件修改时间和客户端创建时间任一较新都会保留对象。规划完成前不删除；删除阶段不是跨文件事务，IO 错误可能产生部分删除，可在排除错误后重试。仍被引用的对象不会进入删除计划。

SQLite 回收在一个事务中删除记录，保留原有位置；失败整体回滚。数据版本标记升级为 4，阻止不认识退休事件的旧版实现打开库。没有自动降级。

InspectRetention 只是盘点，不遍历 blob 内容，不得直接用于删除。
