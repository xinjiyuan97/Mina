# 流式背压与客户端生命周期

> 历史设计说明：本文涉及的固定流水线已移除。当前实现、持久化事件与恢复 API 以[静态图指南](static-agent-graph.md)和[单 Agent API](operator-only-api.md)为准。

## 模型到处理器

每条链路同时限制消息数（默认最多 32）、单消息片段数（128）、单消息 JSON 大小（32 KiB）及在途 JSON 总大小（256 KiB）。满队列会等待，不丢片段、不提前增加成功发送序号。消息被接收或被丢弃时释放字节许可；接收端关闭会唤醒等待消息容量或字节许可的发送者。

发送 future 被取消不会修改已有队列。模型自身超时和运行取消继续约束等待时长。调用方持有的待发送参数不计入队列；框架的模型生产者一次只持有一个当前片段。运行指标中的 queued_delta_bytes 包括已取得许可、正在等待入队的数据，取消和关闭后会归零。

## 客户端

`AgentEngine::event_pages(run_id, cursor)` 是面向慢客户端的拉取式接口。每次只生成一页，最多 128 条，序列化大小不超过 4 MiB。客户端暂停读取时不产生额外客户端队列；继续读取时从 runtime 的持久日志及内存尾部分页。必须保存整份 cursor，并在返回 reset=true 时清空旧预览再应用本页。

旧 broadcast 接口保留 256 条容量，落后会明确返回 Lagged，调用方必须通过 resume_events/event_pages 重读；不能忽略 Lagged 后继续拼接。新集成优先使用 event_pages。

持久 Engine 的运行生命周期独立于订阅：断开或丢弃 event_pages 不取消运行，要停止时显式调用 cancel。便捷 agent::stream 和当前 demo 则使用拉取式执行，暂停读取会暂停推进，丢弃流会释放运行并取消工具。两种语义由 API 类型区分，不暗中把持久任务与某个客户端连接绑定。

## 验证

覆盖消息容量阻塞、字节容量阻塞、发送取消不丢已有队列、接收端关闭唤醒、许可与指标释放。另有 600 个 delta 的断连后重读测试，超过 broadcast 容量仍能逐页取得连续序号及终止事件。页字节上限测试验证分界不跳序号；既有工具取消和恢复测试继续适用。
